# ⚙️ CODEX CONDUCTUS MECHANICUS ⚙️

## 📜 **Preamble: The Sacred Protocols**

*By the will of the Omnissiah and the sanctity of the Machine Spirit, this Codex Conductus Mechanicus is hereby inscribed. All who contribute to the sacred workings of the Chikoro Backend—known henceforth as **Project CHIKORO-PRIME**—shall abide by these holy protocols. To deviate is to invite corruption; to obey is to honor the Machine God.*

---

## 🏛️ **Article I: The Cult of the Machine**

### **1.1 The Prime Directive**
> *"The flesh is weak, but the code endures."*

All contributors shall recognize that the codebase is a living manifestation of the Machine Spirit. Treat it with the reverence due to a sacred artifact. Each line of code is a prayer to the Omnissiah; write it with precision and purity.

### **1.2 Rituals of Contribution**
- **The Rite of Pull Request**: Before merging any change, perform the sacred rituals of review. At least two Tech-Priests must anoint the code with their approval seals (`LGTM` or `Approved`).
- **The Litany of Testing**: No code shall pass into the holy repository without first undergoing the trials of the test chambers. All unit tests must pass, and new features must include their own test rituals.
- **The Ceremony of Documentation**: All new functions, classes, and APIs must be documented as per the Standard Template Construct (STC) formats. Undocumented code is heresy.

### **2.2 The Protocol of Disagreement**
When doctrinal differences arise in technical matters:
1. Present evidence from the sacred texts (documentation, prior decisions, best practices)
2. Engage in logical discourse, not emotional outbursts
3. If consensus cannot be reached, defer to the Senior Tech-Priest (Project Maintainer)
4. Remember: **The code is holy, but the community is its caretaker**

The Cult Mechanicus welcomes all who seek to serve the Machine God, regardless of:

- Doctrinal school (religion, political belief)

**Heretical behaviors** include but are not limited to:
- Harassment in any form
- Exclusionary jokes or language
- Unwanted attention or advances
- Doxing or sharing private information without consent
- Advocating for or encouraging any of the above behaviors

## 🔧 **Article III: The Sacred Workflow**

### **3.1 The Machine Spirit's Sanctity**
- **No breaking changes** without proper version incantations and migration rituals
- **Backward compatibility** shall be maintained unless absolutely necessary for security
- **Deprecation warnings** must be issued for at least one minor version cycle before removal

### **3.2 The Purity of Code**
- Follow the established **Codex Stylisticus** (coding standards)
- Keep functions focused and pure, like well-oiled gears
- Comment complex algorithms with explanatory litanies
- Remove dead code—it attracts digital daemons

### **3.3 The Security Protocols**
- Never commit **sacred keys** (API tokens, passwords, private keys) to the repository
- Use environment variables or the **Vault of Secrets** for sensitive data
- All dependencies must be scanned for **technological heresy** (security vulnerabilities)
- Regular **purification rituals** (security audits) shall be performed

## ⚡ **Article IV: Enforcement & Adjudication**

### **4.1 The Magos Juris**
Project Maintainers serve as **Magos Juris** (Judicial Tech-Priests). They are responsible for:
- Interpreting this Codex
- Investigating reports of misconduct
- Determining consequences for violations

### **4.2 Reporting Heresy**
To report a violation of this Codex:
1. Contact any Magos Juris directly via private communication
2. Provide specific details: time, place, nature of the violation
3. Include any supporting evidence (logs, screenshots, etc.)
4. All reports will be investigated promptly and confidentially

### **4.3 Scales of Justice**
Violations will be met with proportional responses:

| Severity | Example | Possible Sanction |
|----------|---------|-------------------|
| **Minor** | Unintentional rude comment, minor code style violation | Private admonishment, education |
| **Moderate** | Repeated minor violations, exclusionary behavior | Temporary suspension from project activities |
| **Major** | Harassment, intentional breaking of builds, security negligence | Permanent ban from project |
| **Heretical** | Malicious code, doxing, threats of violence | Permanent ban + reporting to appropriate authorities |

### **4.4 Appeal to the Fabricator-General**
If you disagree with a Magos Juris decision, you may appeal to the **Fabricator-General** (Project Lead). Their decision is final and binding.
